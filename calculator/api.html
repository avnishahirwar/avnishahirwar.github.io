Friendly Calculator API

Use one secure JSON endpoint to run the same calculator models available on Friendly Calculator. Requests are processed on the server, validated and recorded against the API key's plan quota.

20 calculators HTTPS JSON POST

Keep your API key secret. Call this API from your own trusted server. Do not place an API key in public browser JavaScript, a mobile application package, a public repository or a shared screenshot. The dashboard's Try API tool is intended for private testing while signed in.

1. Base URL and authentication

POST https://gtuycqunlihegsbvvsol.supabase.co/functions/v1/calculator-api

Required headers:

Content-Type: application/json
x-api-key: avsk_live_YOUR_PRIVATE_KEY

All 20 calculators use this single endpoint. Select the calculator with the JSON calculator property. The key must be active, have the calculators:read scope and have API access enabled with remaining quota.

3. Request and response example

GST example request:

{
  "calculator": "gst",
  "inputs": {
    "amount": 10000,
    "rate": 18,
    "mode": "add",
    "supply": "intra-state"
  }
}

Example response:

{
  "ok": true,
  "calculator": "gst",
  "result": {
    "taxableAmount": 10000,
    "gstAmount": 1800,
    "totalAmount": 11800,
    "rate": 18,
    "mode": "add",
    "supply": "intra-state",
    "cgst": 900,
    "sgst": 900
  },
  "usage": {
    "plan": "business_monthly",
    "quota": 1000,
    "used": 1,
    "remaining": 999,
    "rate_limit_per_minute": 60
  }
}

The example values illustrate the response structure. The actual usage fields are returned from the account's active plan and quota.

4. Copy-ready integrations

cURL

curl -X POST 'https://gtuycqunlihegsbvvsol.supabase.co/functions/v1/calculator-api' \
  -H 'Content-Type: application/json' \
  -H 'x-api-key: YOUR_PRIVATE_API_KEY' \
  -d '{"calculator":"emi","inputs":{"principal":500000,"annualRate":9,"years":5}}'

JavaScript (Node.js server-side)

const response = await fetch(
  "https://gtuycqunlihegsbvvsol.supabase.co/functions/v1/calculator-api",
  {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "x-api-key": process.env.FRIENDLY_CALCULATOR_API_KEY
    },
    body: JSON.stringify({
      calculator: "emi",
      inputs: { principal: 500000, annualRate: 9, years: 5 }
    })
  }
);
const result = await response.json();
if (!response.ok) throw new Error(result.error || "API request failed");
console.log(result.result);

Python

import os
import requests

response = requests.post(
    "https://gtuycqunlihegsbvvsol.supabase.co/functions/v1/calculator-api",
    headers={
        "Content-Type": "application/json",
        "x-api-key": os.environ["FRIENDLY_CALCULATOR_API_KEY"],
    },
    json={
        "calculator": "emi",
        "inputs": {"principal": 500000, "annualRate": 9, "years": 5},
    },
    timeout=20,
)
response.raise_for_status()
print(response.json()["result"])

Store FRIENDLY_CALCULATOR_API_KEY in your server's secret environment configuration. Do not hard-code it in client-side code.

5. Usage limits

  • Every calculator request uses the same API key and is subject to its per-minute rate limit.
  • Monthly quota and rate limits are enforced by the server, not by dashboard controls.
  • Valid-key requests that reach calculation processing count toward monthly quota, including invalid-input responses.
  • Requests rejected for invalid keys, disabled API access, exhausted quota or rate limits do not consume monthly quota.
  • Try API sends a real production request and counts toward quota and rate limits when it reaches processing.
  • The Free plan currently has no API access by default. API access requires an enabled API plan or an administrator-granted quota. The Business plans in the existing plan catalogue include API access; subscription checkout is not currently active.

7. Manage keys and test requests

Sign up or sign in to the Customer API Dashboard to create a key, copy it once, revoke unused keys, inspect usage and send a real test request. Keys are stored as SHA-256 hashes; the raw key is never retrievable after creation.
